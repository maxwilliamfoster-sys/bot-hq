# Bot HQ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A home-screen phone app that does three things for the three content bots:
- pushes a notification the moment something needs the owner, a post fails or does well, a post goes out, or the daily summary is ready
- shows live analytics with a custom graph builder
- gives a copy-paste Claude prompt for every failure

**Architecture:**
- One Cloudflare Worker `bot-hq` serves the PWA (`public/`), a JSON API, D1 `bot-hq-db`, and Web Push (`@pushforge/builder`).
- Bots send instant events through a shared `app_events.py`.
- A 5-minute cron watches GitHub Actions runs, YouTube stats and Buffer metrics.
- A nightly GitHub Action (`ingest/backfill.py`) loads history from the bots' committed files.

**Tech Stack:**
- Worker: Node 24, wrangler 4, Cloudflare Workers + D1 (free tier), `@pushforge/builder`.
- UI: Chart.js bundled by esbuild, vanilla JS modules.
- Tests: `node --test`, with D1 faked by `node:sqlite`. Python 3.11 `unittest` for `app_events.py` and the backfill.

  - YouTube Data API: 10k units/day.
  - GitHub Actions: on a **public** repo (see Ruling R1).
- **Secrets never touch the repo.** They live only in `wrangler secret put` / GitHub secrets / `.dev.vars` (gitignored). Worker secrets:
  - `ACCESS_CODE_HASH`, `APP_EVENTS_TOKEN`, `VAPID_PRIVATE_JWK`, `YT_API_KEY`, `GH_READ_TOKEN`

  Var: `VAPID_PUBLIC_KEY`.

- **Severities** are exactly `action`, `warn`, `good` and `info`. Inbox filter chips map to them: Needs you = action, Failed = warn, Doing well = good, Posted = kind `posted`, Summary = kinds `summary` and `digest`.
- **All time logic uses `Europe/London`:**
  - Default quiet hours are 22:30–07:00. `action` is always pushed.
  - The daily summary goes at 07:30 UK.

## Rulings (decided before execution)
- **R1:** The spec said the `bot-hq` repo is private. It is **public** instead. Private repos share the account's 2,000 free Actions minutes with the private chess bot, which already uses most of them. The repo holds only code; all data sits behind auth in D1 and all secrets are in Worker/GitHub secrets. Cost if wrong: the app's source is readable, and nothing else is exposed.
- **R2:** History backfill runs as Python in a GitHub Action, not inside the Worker. Parsing the bots' JSON/CSV files (hundreds of KB) risks the free 10 ms CPU limit. Ongoing data comes from the Worker's polls plus `posted` events.
- **R3:** The morning `needs_you` checks stay in `chess-puzzle-automation/needs_you.py`. `loop_nightly` emits each line as its own `action` event, and the digest text as an `info` `digest` event that is not pushed. The Worker adds only the real-time checks: run failures, posting gaps, and an empty Escape queue.

## Review Focus
1. **The app is down when a bot alerts.** The alert must still reach Telegram. Test: Task 6, `test_emit_falls_back_to_telegram_when_app_down`.
2. **A phone's push subscription expired (404/410).** It is deleted, the other devices still get the push, and nothing throws. Test: Task 3, `pushAll removes gone subscriptions`.
3. **The same failure every 2 hours.** One grouped event; it pushes on the 1st and 3rd occurrence within 24 h, not every time. Test: Task 5, `repeat failures are grouped and pushed at 1st and 3rd`.
4. **The clock change on 2026-10-25 (BST to GMT).** Quiet hours and the 07:30 summary follow UK local time on both sides of the change. Test: Task 3, `quiet hours follow UK time across the clock change`.
5. **The failed-run log can't be fetched, or is huge.** The event is still created and the prompt says the log was unavailable. Test: Task 7, `log fetch failure still alerts`.
